# Reproduction

Use only `.venv-rag\Scripts\python.exe` from the repository root. Existing CUDA torch 2.11.0+cu128 must be preserved. `requirements.txt` lists project additions, and the generated lock file records all actually installed versions. Do not apply the lock file blindly on a different platform: CUDA torch needs its appropriate existing installation and package index. There are no global pip operations, driver changes, new virtual environments or WSL changes.

An intermittent Windows FAISS DLL initialization failure was observed when FAISS loaded after PyTorch. Application entry points and tests now load FAISS first, with thread environment variables configured before native-library loading. The preflight passed with this order. In a combined Member B application, use `import faiss` before `import torch`; the JSON CLI is also a separate-process integration option. Do not address a native DLL error by silently changing the backend or replacing the working CUDA torch.

DataLoader collators and worker seeding live in `src/tokenization.py`, which never imports FAISS: spawned workers only tokenize on CPU. This separates native-library initialization from worker unpickling. The running serial implementation was archived in `results/source_snapshots/serial_source.zip` before this worker-module refactor; tokenization, seeds and all numerical operations are unchanged. Per-run source SHA-256 hashes distinguish the versions. The serial process uses zero workers throughout.

Downloaded SciFact raw files and model weights are local caches, excluded from Git. `retrieval.py prepare` validates existing raw checksums rather than redownloading; `download-model` validates cached model checksums. Dataset manifest records source, HF commit, config version, UTC download time and content digests. The official `latest` archive is mutable upstream: these local checksums identify the exact studied bytes. A future fresh download with different hashes is a new dataset version, even if the URL is unchanged.

On a source-only checkout with existing manifests, missing model files are fetched at the recorded revision and missing dataset files restored from the official archive only if its SHA-256 still matches the recorded release. If upstream `latest` changes, restore your archived data cache; the loader refuses a silent dataset substitution. Missing historical HF API metadata (which contains mutable counters) is reported separately and is never fabricated. All corpus, claims, schema and archive contents must still match their recorded checksums.

Save the cache alongside raw measurements for archival reproduction. Model revision is pinned when downloaded, saved in the model manifest, and loaded locally for every mode; inference does not contact Hugging Face. The index metadata binds vectors to model/data fingerprints, document IDs, config and checksums. Benchmarks rebuild all document vectors each repeat rather than taking cached vectors as an unexplained advantage.

Run `scripts/run_experiments.py` for the full sequential matrix; default five warm trials per configuration. Run `retrieval.py summarize`, `retrieval.py plots`, and `python -m pytest -q` for reports and verification. Unit fixtures are explicitly synthetic and isolated from experiments. Tests requiring real model/data skip only if those downloads are absent; inspect the actual test report before claiming a complete pass.

If CUDA fails on a future machine, `retrieval.py hardware` preserves CPU functionality and reports diagnostics. Do not claim CUDA measurements. A Colab fallback is appropriate only then: select a GPU runtime, copy the source, install missing project dependencies without unnecessarily replacing preinstalled torch, run hardware/prepare/download-model, then CUDA smoke/tests and benchmarks. Record Colab's actual GPU, package versions and resource limits separately. Those results are from different hardware and are not a replacement for laptop speedups. No paid Colab or cloud operations are performed by these scripts.
